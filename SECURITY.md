# Security Policy

## Overview

Thank you for helping improve the security, reliability, and integrity of the BQEB-ForecastBench project.

BQEB-ForecastBench is a research benchmark framework for evaluating AI and machine learning models for smart grid forecasting using the BIO-Quantum Energy Brain (BQEB) dataset and evaluation methodology.

We welcome responsible reporting of security issues, data integrity concerns, and reproducibility problems.

---

## Supported Versions

The latest version of the repository is actively maintained.

| Version | Supported |
|---------|-----------|
| Latest release | ✅ Yes |
| Main branch | ✅ Yes |
| Older versions | ⚠️ Limited support |

Security fixes and improvements will be applied to the latest maintained version.

---

## Reporting a Vulnerability

Please do not publicly disclose security vulnerabilities through GitHub Issues.

Security concerns can be reported privately using:

- GitHub Security Advisories ("Report a vulnerability" option)
- Private communication with the repository maintainer

**Maintainer:**

Rakesh Kumar Agrawal

When reporting an issue, please include:

- Description of the vulnerability
- Affected component or file
- Steps to reproduce the issue
- Potential impact
- Recommended mitigation (if available)

---

## Response Process

Reported issues will be reviewed and evaluated based on severity.

Expected response:

- Initial acknowledgment within 7 days
- Investigation and validation of the reported issue
- Resolution guidance or mitigation where applicable

---

## Scope

This security policy applies to:

- Source code
- Benchmark pipelines
- Evaluation scripts
- Dataset processing workflows
- Configuration files
- Dependencies
- Documentation and experiment artifacts

---

## Data and Research Integrity

BQEB-ForecastBench is intended for scientific research and reproducible AI benchmarking.

Please report concerns related to:

- Dataset corruption or unauthorized modification
- Incorrect benchmark results
- Reproducibility issues
- Experimental pipeline vulnerabilities
- Incorrect attribution or citation
- Accidental exposure of sensitive information

---

## Responsible Disclosure

We request that security researchers and contributors:

- Avoid public disclosure before review
- Provide sufficient technical details for validation
- Allow reasonable time for investigation and remediation

Responsible reports help improve the quality, transparency, and trustworthiness of this research benchmark.

---

## Acknowledgments

We appreciate researchers, contributors, and reviewers who responsibly identify issues and help strengthen the security, reliability, and scientific value of BQEB-ForecastBench.
